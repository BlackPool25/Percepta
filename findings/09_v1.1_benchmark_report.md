## What Changed from v1 to v1.1

### Architecture changes

1. **Interleaved replay during consolidation** (`gate.py:validate_and_commit`): The Stage 2 shadow model now fine-tunes on joint candidate + replay data, not candidate alone. This converts the gate from passive detection to active protection.

2. **Ongoing replay in main training loop** (`train.py:train_two_stage_gate`): Every training batch now includes a replay batch from committed clusters. This is the critical missing piece — without it, committed knowledge is overwritten by subsequent task training.

3. **Core-set protected buffer** (`buffer.py`): On promotion, each cluster reserves a fixed-size core-set (100 examples) that survives FIFO eviction. This ensures replay data persists for the lifetime of the experiment.

4. **Sparse fc1 activation** (`model.py`): k-winners-take-all (k=64, 25% of 256 fc1 units) applied during training. Reduces representation entanglement by forcing competitive sparse activation. Applied uniformly across all 3 configs for fair comparison.

### Bug fixes

5. **Forgetting sign inversion** (`gate.py:135`): Fixed `forgetting = old_replay_loss - new_replay_loss` → `forgetting = new_replay_loss - old_replay_loss`. Original allowed actual forgetting to pass validation.

6. **Buffer logging optimization** (`train.py`): Changed from per-sample logging (128 buffer ops per batch) to per-class logging (2 per batch). Removed a major throughput bottleneck.

### Parameter tuning

| Parameter | v1 Default | v1.1 Value | Reason |
|-----------|-----------|------------|--------|
| `freq_threshold` | 50 | 500 | v1 triggered Stage 1 after 1 batch; delayed to require real accumulation |
| `eps_gain` | 0.01 | 0.001 | v1 threshold was too strict for low-error converged models |
| `eps_forget` | 0.05 | 0.50 | Allow more replay degradation during consolidation; real protection comes from ongoing replay |
| `core_size_per_cluster` | 0 (none) | 100 | Sweep showed plateau at 100; 10→50 improved linearly, 75→128 plateaued |
| `k_wta` | 0 (dense) | 64 | Sparse fc1 improved ACC +0.011, BWT +0.017 in A/B test |

## What v1.1 Proves

1. **The two-stage gate mechanism works.** With active replay (both during commit and ongoing training), the gate reduces forgetting by ~80% compared to naive sequential fine-tuning.

2. **Diagonal Fisher EWC remains structurally insufficient.** Even with sparse fc1 (which should densify the Fisher signal), EWC produces naive-identical results. The distributed-representation collapse is not fixable via per-parameter regularization at this scale.

3. **Replay is carrying the protection load.** The Fisher mask in the gate contributes negligible protection. The actual forgetting-prevention comes from interleaved replay. This aligns with modern continual learning literature (replay consistently outperforms regularization-only methods).

4. **Core-set sizing matters.** 10-50 examples per cluster showed linear improvement. 100 hit the plateau for Split-MNIST's 2-class subtasks. Larger environments will need proportionally larger core-sets.

5. **Sparse activation helps marginally.** k-WTA on fc1 improved ACC by 1.5% and BWT by 10% relative. The effect is real but small — sparsity alone doesn't solve entanglement, but it helps replay be more effective.

---

## Caveats and Limitations

1. **1 epoch per task is minimal training.** With more epochs, the gate may perform even better (more buffer samples, better core-sets) or worse (more opportunity for replay to fail). Not tested.

2. **All clusters were promoted.** By task 4, all 10 digit classes were committed. The Stage 1 filter (`freq_threshold=500`) didn't reject any class. In a noisier environment with rare classes, this filter would matter.

3. **Task 2 (digits 4,5) shows the weakest retention.** 57.6% retention vs 91-95% for tasks 0-1. This suggests the replay mechanism degrades as more clusters are added — the replay batch gets diluted across more committed classes.

4. **EWC remains the wrong baseline.** The comparison is effectively "gate vs naive." A replay-based baseline (naive + experience replay without gating) would be a more meaningful comparison for v1.2.

5. **The fast-weight layer is not yet built.** v1.1 still uses the slow layer only. The full fast/slow split (v2) would add a separate fast-weight adapter that learns moment-to-moment, reducing pressure on the slow layer.

---

## Decisions Locked by v1.1

| # | Decision | Rationale |
|---|----------|-----------|
| D7 | Replay is the primary protection mechanism | Fisher masks are directionally valid but structurally insufficient. Ongoing replay must carry the forgetting-prevention load. |
| D8 | Core-set buffer is necessary infrastructure | FIFO eviction loses the data replay needs. Core-set protection (fixed-size per committed cluster) is the minimum viable buffer design. |
| D9 | Phase 5 (MESU metaplasticity) is deferrable | The gains from sparse fc1 are small (+1.5% ACC). MESU-style learning rate modulation is unlikely to be transformative without the fast/slow split. |
| D10 | core_size_per_cluster = 100 for Split-MNIST | Sweep confirmed plateau. Future environments will need proportional sizing. |

---

## Next Steps (v1.2 or v2)

1. **Add a replay-only baseline.** Run naive + experience replay (no gate, no Fisher) on the same setup. This isolates the gate's added value from replay's contribution.

2. **Fix task-2 retention weakness.** Diagnose why digits 4,5 suffer the most forgetting (class confusion? core-set sampling bias? order effects?).

3. **Test with more epochs.** 1 epoch is speed-optimal for prototype cycles but hides convergence effects. 5-10 epochs per task would stress-test the replay mechanism.

4. **Add fast-weight layer (v2).** A separate fast adapter (small Hebbian/outer-product weights) that learns moment-to-moment would reduce the slow layer's adaptation burden and potentially improve retention further.

5. **Scale to noisier benchmarks.** Permuted MNIST or CIFAR-10 split would test whether the mechanism holds when task boundaries are less clean.

```bash
    --configs naive ewc two_stage_gate \
    --seeds 42 43 44 45 46 \
    --epochs 1 \
    --freq-threshold 500 \
    --eps-gain 0.001 \
    --eps-forget 0.50 \
    --core-size 100 \
    --k-wta 64 \
    --output-dir results/my_run
```
